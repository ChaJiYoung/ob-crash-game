### 0-2. 폰 흉내 내기

실제 폰 대신 WebSocket 스크립트로 서버에 붙는다. 예시는 [scripts/capture-coop-impl.mjs](./scripts/capture-coop-impl.mjs)의 `fakePhone` (`ws`는 저장소 `node_modules/ws/wrapper.mjs`).
- 연결: `REGISTER_NICKNAME { roomId, deviceId, nickname, slot }` → PC에 슬롯 카드가 "접속 완료"로 바뀌어야 함
- 영점: `CALIBRATE_ZERO { roomId, deviceId, slot }`
- 조준: `SENSOR_FRAME { slot, payload: { aimX, aimY, ... } }`를 30ms 간격으로 계속 보낸다(−1~1)
- 단발: `snapFire: true` 프레임 1개 / 연사: `rapidFireHold: true`를 유지했다가 false / 피버: `feverTriggered: true` / 스킬: `skillSnapTriggered: true`
- 끊김: 소켓 `close()` / 재접속: 새 소켓으로 `DEVICE_CHECK { roomId, deviceId, slot }` 후 `CALIBRATE_ZERO { …, resume: true }`
- 방 코드: PC 페이지 `localStorage.getItem('beer_crusher_pc_room_id')`
- 진짜 폰 컨트롤러 화면도 한 번 보려면 Playwright 두 번째 페이지로 `https://127.0.0.1:<포트>/controller?room=<방>&slot=2`를 연다(센서 권한 화면까지만 확인해도 된다).

### 0-3. 판정 기준

- **문제(BUG)**: 오류·크래시(브라우저 `pageerror`·콘솔 에러 포함), 조작이 안 먹음, 엉뚱한 플레이어에게 적용, 화면 요소 겹침·잘림·누락, 결정과 다른 동작

## 4. 산출물

각 QA 에이전트는 자기 산출물 폴더에:
1. 캡처 PNG: 체크 항목마다 근거가 되는 화면. 파일명은 `<항목번호>-<짧은이름>.png`(예: `B-07-combat-coop.png`)
2. `report.md`: 위 체크리스트를 복사해 각 항목을 PASS / BUG / DIFF / SKIP으로 표시하고, BUG·DIFF는 **재현 순서, 기대, 실제, 캡처 파일명**을 적는다. 브라우저 `pageerror`·콘솔 에러는 전부 기록한다.
3. 사용한 스크립트는 `scripts/`에 둔다(나중에 다시 돌릴 수 있게).
4. 끝나면 `touch .memory/.done-QA-<A|B|C>`(커밋 금지), 진행 불가면 `touch .memory/.blocked-QA-<A|B|C>` 후 이유를 report.md에 적는다.
5. 저장소 코드(src/, server/, tests/)는 수정하지 않는다. 띄운 서버 프로세스는 끝날 때 종료하고 임시 vite 설정 파일은 지운다.

## 5. 2차 QA(R2) 추가 지시 — 1차에서 놓친 것 보강

2차 산출물 폴더는 `.memory/references/two-player-coop-qa-r2/<A-solo|B-mouse-phone|C-phone-phone|D-fullplay-mouse|E-fullplay-phone>/`. 1~4장 항목을 처음부터 다시 확인하고, 아래를 더한다.

### 5-1. 판정은 콘솔이 아니라 결과로
- 누른 채 연사: 마우스는 버튼을 1초 누르고 있기, 폰은 `rapidFireHold: true`를 1초 유지. **탄약이 여러 발 줄었는지**(`window.__BEER_DEBUG__.snapshot().players[i].ammo` 전후 비교)로 PASS 판정. 콘솔 에러 없음도 함께.
- 피버 자동 연사: 피버 발동 후 2초 동안 해당 플레이어 점수·처치가 늘고 사격 효과가 나오는지 snapshot 값으로 확인.
- 브라우저 `pageerror`와 `console.error`는 시나리오 전체에서 0건이어야 PASS. 1건이라도 있으면 BUG로 전문을 적는다.

### 5-2. 총구 조준(정량)
- 2인 판에서 아래 조준 조합마다 캡처한다: (1P 왼쪽 위 −0.7, 0.4 / 2P 오른쪽 아래 0.7, −0.3), (1P 오른쪽 0.6, 0.0 / 2P 왼쪽 −0.6, 0.0 — 서로 교차), (둘 다 가운데 0, 0). 1인 판은 네 모서리(±0.7, ±0.4)와 가운데.
- 판정: 캡처에서 총신(총구 쪽 긴 부분)의 축을 화면 위쪽으로 연장한 선이 **자기 십자선 중심에서 십자선 바깥 고리 반지름 이내**를 지나면 PASS. 교차 조합에서 두 총이 서로 반대쪽으로 꺾여야 한다. 애매하면 BUG가 아니라 DIFF로 적고 캡처를 남긴다(눈대중 PASS 금지).

### 5-3. 화면 경계
