# QA-B (R2) 보고서 — 2인 마우스+폰 / 폰+마우스

- 담당: 2차 QA-B (인수: Gemini 1차 잔여분)
- 조합: **mp** = 1P 마우스·2P 폰 / **pm** = 1P 폰·2P 마우스
- 환경: 게임 서버 8802, 개발 서버 5202(`_vite-configs/vite.qa-B.config.ts`를 임시 복사, 종료 후 삭제). Playwright 실제 브라우저 + WebSocket 가짜 폰.
- 판정 원칙: 스냅샷 값(`window.__BEER_DEBUG__.snapshot()`)·DOM 텍스트·캡처 근거. 눈대중 PASS 없음.
- 최종 실행 로그: `scripts/run-mp.log`, `scripts/run-pm.log`, 값 JSON: `values-mp.json`, `values-pm.json`
- 스크립트: `scripts/qa-b-r2-verify.mjs <mp|pm>`(이번 판정의 주 스크립트), `scripts/diag-slot-move2.mjs`(슬롯 이동 진단), `scripts/qa-b-r2-combo2.mjs`(인수 시 미기록 실행, 참고용)
- 실행 이력 로그(`scripts/run1-*`, `run2-*`, `run3-*`, `run4-prev-*`, `run5-*`)는 중간에 깨진 실행이며 판정에 쓰지 않음(실패 원인은 아래 "스크립트 수정 이력").
- 캡처 접두사: `V-mp-*`, `V-pm-*`(이번 실행), `B2-*`(combo2 인수 실행), `B-*`(Gemini 1차, 검토 안 함)

### BUG-1. 같은 기기가 다른 슬롯 QR로 다시 붙으면 슬롯이 이동하지 않고 두 슬롯에 동시에 남음 — **확정**
- 재현(진단 `scripts/diag-slot-move2.mjs`):
  1. 폰 기기 X를 슬롯 2로 `REGISTER_NICKNAME` → 슬롯 2에 "모바일P" 표시
  2. 같은 기기 X를 슬롯 1로 `REGISTER_NICKNAME`
  3. 같은 기기 X를 슬롯 2로 다시 `REGISTER_NICKNAME`
- 기대: 2단계에서 닉네임이 슬롯 1로 이동하고 슬롯 2가 비워짐. 3단계는 다시 슬롯 2로 이동.
- 실제:
  - 2단계 후: 슬롯 2에 여전히 "모바일P"(🖱 마우스 disabled), 슬롯 1은 비어 있음(마우스 활성)
  - 3단계 후: 슬롯 1·2 모두 "모바일P님 접속 완료", 두 카드의 🖱 마우스 버튼 **disabled**, 슬롯 1은 "연결이 끊어졌습니다. 다시 연결 중…"
  - 결과적으로 마우스 플레이어가 어느 슬롯에도 들어갈 수 없음 → 실행 중 `locator.click` 타임아웃으로 멈춤(run1 mp, run1 pm, 진단 모두 재현)

## 4. 검사 스크립트 수정 이력(제품 결함 아님, 재현 불가 BUG 정리용)

4. 07c: 일시정지 메뉴 버튼 문구는 "이어하기"(기존 "계속하기" 셀렉터 오류).
5. 08a: 같은 이유.
6. 결과 나가기: "로비로 나가기"는 확인 대화상자를 연다. 확인 버튼 "나가기" 클릭 추가.
7. 게임 1: 봇 사격 6분 제한 대신 4분 뒤 사격 중지(판 종료 확보).
8. 11a·11b: 결과 화면 검사 문구는 위 BUG-2로 확정.
