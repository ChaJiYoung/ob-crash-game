# 2차 QA 인수인계 (Gemini → Claude Haiku)

Gemini 3.8 Flash QA 에이전트 5개가 사용량 한도로 **보고서(`report.md`)를 쓰기 전에** 멈췄다. 이어받는 에이전트는 자기 폴더의 기존 산출물(캡처·JSON·scripts)을 먼저 읽고, 아래 "남은 것"을 끝낸 뒤 보고서를 쓴다.

- 지시 원문: [../two-player-coop-qa-checklist.md](../two-player-coop-qa-checklist.md) (1~4장 기본, **5장 2차 추가 지시**)
- 시안: [../two-player-coop-mockups.md](../two-player-coop-mockups.md), 결정: [../../decisions/2026-11-07-two-player-coop.md](../../decisions/2026-11-07-two-player-coop.md)
- 개발 서버에서 `window.__BEER_DEBUG__.snapshot()`으로 상태·표적 조준 좌표를 읽을 수 있다(읽기만).
- 각 폴더의 `scripts/`에 Gemini가 쓰던 스크립트가 있다(서버 실행 스크립트 포함). 재사용하되 그대로 믿지 말고 결과를 검증한다.
- Gemini가 만든 임시 vite 설정은 `_vite-configs/`에 옮겨 두었다. 서버를 다시 띄울 때 저장소 루트로 복사해 쓰고, 끝나면 루트 사본을 지운다. **저장소 루트에 산출물 폴더를 만들지 않는다**(산출물은 이 폴더 아래에만).

## 먼저 확인할 의심 신호(모든 에이전트 공통 관심사, 담당 지정)

1. **누른 채 연사가 브라우저에서 동작하는가** — 담당 A(마우스), C(폰)
   - Gemini 측정: C `flow1-results.json` 1초 홀드 탄약 감소 1발(개틀링·샷건), D `match-record-shotgun.json` 1발, E `fullplay-summary.json` 1발(`pass:false`).
   - 리뷰어 확인: **엔진 직접 호출로는 정상**(1초 홀드 시 개틀링 11발, 샷건 6발, 리볼버 7발). 따라서 브라우저 경로(어댑터 → 처리부 인터벌 → 엔진) 문제이거나 측정 스크립트 문제다.
   - 할 일: 마우스는 표적 근처를 겨눈 채 `mouse.down()` → 100ms 간격 10번 `snapshot().players[0].ammo` → `mouse.up()`. 폰은 `rapidFireHold: true` 프레임을 30ms 간격으로 1초. 탄약이 여러 발 줄면 PASS. 1발만 줄면 **BUG**로 적고, 브라우저 콘솔에 `window.__BEER_DEBUG__` 외 추가 로그 없이 재현 순서를 정확히 남긴다(원인 추측은 "추정"으로 표시).
2. **폰 끊김 시 30초 유예 화면** — 담당 C
   - Gemini 기록(`c05-c10-results.json`): `hasAloneBtn: false`, `p2AwayConfirmed: false`. 그런데 그 시점 화면 텍스트가 무기 선택 화면이었다 → **게임 시작 전(무기 선택 중)** 끊었을 가능성. 유예 규칙은 `PLAYING` 단계에서만 동작한다.
   - 할 일: 무기 선택을 끝내고 전투 중에 끊어서 다시 확인. 무기 선택 중에 끊기면 어떻게 되는지도 따로 기록(결정에 없는 경우라 DIFF/관찰로).
3. **풀플레이가 매우 느림** — 담당 D, E
   - Gemini 기록: 웨이브 1에 217~262초(기준 14~18초). 봇 조준이 표적을 제대로 못 맞혔을 가능성이 크다.
   - 할 일: 봇이 매 프레임 `snapshot().targets` 중 `landed && !isItem && !selectKind`인 가장 가까운(`radiusM` 작은) 표적의 `aimX/aimY`를 겨누고, 명중률을 함께 기록한다(사격 수 대비 처치·점수 변화). 마우스 좌표 변환은 `x = (aimX+1)/2*width`, `y = (1-aimY)/2*height`. 명중률이 낮으면 봇 문제로 보고 고친 뒤 진행.

## 담당별 진행 상황과 남은 것

### A-solo (1인)
- 한 것: 마우스 1인 로비→닉네임 자동 채움→무기 선택→전투 HUD→사격→Esc→보상 카드 캡처(A-1-01~08), 총구 5방향 캡처(A-5-2-*), 콘솔 에러 0(`a1-test-summary.json`).
- 남은 것: 체크리스트 A-1 나머지(결과 화면·로비 복귀), A-2 폰 1인(1P 슬롯), A-3 폰 1인(2P 슬롯만), A-4 튜토리얼·센서 랩, 5-1(연사·피버 값 확인 — 위 의심 신호 1), 5-2 총구 판정(기존 A-5-2 캡처를 기준대로 판정만 해도 됨), 5-3 경계(1440×900, 1024×768), 5-4, report.md.
- 포트: 게임 8801 / 개발 5201.

### B-mouse-phone (2인 마우스+폰, 폰+마우스)
- 한 것: 로비 시작 게이트·슬롯 거절·무기 선택·교차 사격·부분 선택·전투 HUD·스킬 배지·십자선·총구 3조합(B-10-gun-aim-*)·광선·입력 분리·HUD 버튼·Esc·결과·재시작 캡처, 로비 경계 측정(`boundary-report.json`).
- 남은 것: **폰+마우스(1P 폰·2P 마우스) 조합을 실제로 했는지 불명확** — 스크립트 `qa-b-r2-combo2.mjs`를 확인하고 없으면 수행. 5-1 연사·피버 값, 5-2 총구 판정(B-10 캡처로), 5-3 나머지 화면(전투·선택·결과) 경계, 기록 저장(`data/play-records.jsonl`의 `"mode":"coop"` 두 줄), report.md.
- 포트: 8802 / 5202.

### C-phone-phone (2인 폰+폰, 끊김, 결과)
- 한 것: 로비·카운트다운·마우스 HUD 클릭·무기 선택 분할·전투 HUD·끊김 카운트다운·재개·이탈 표시·이탈 자동 선택·복귀·동시 끊김 캡처, 총구 3조합(C-5-2-*), 연사 측정(의심 신호 1).
- 남은 것: 의심 신호 1·2 재확인, 결과 화면(이탈자 "나감", 폰 사격으로 결과 버튼), 난이도 체감(같은 무기로 1인 대비 처치 타수), 5-2 판정, 5-3, report.md.
- 포트: 8803 / 5203.

### D-fullplay-mouse (마우스 1인 풀플레이)
- 한 것: 샷건 판 시작, 연사·피버·스킬 시험, 웨이브 1 클리어(262초)와 보상 카드, 웨이브 2 시작까지.
- 남은 것: 의심 신호 3 해결 후 **샷건·리볼버·개틀링 각 1판을 7웨이브 끝(승리 또는 게임오버)까지**. 웨이브별 기록(시간·목숨·보스·카드·콘솔 에러), report.md.
- 포트: 8804 / 5204.

### E-fullplay-phone (폰 1인 풀플레이)
- 한 것: 샷건 판 웨이브 1~2(각 약 220초), 웨이브 3 보스 등장까지(10분 시간 제한에 걸림), 결과 화면 캡처.
- 남은 것: D와 같다(폰 입력으로). 시간 제한은 판당 20분으로 늘린다.
- 포트: 8805 / 5205.

## 끝낼 때
- report.md(체크리스트 항목별 PASS/BUG/DIFF/SKIP + 근거 값·캡처 + BUG 재현 순서)를 자기 폴더에 쓴다.
- 띄운 서버를 종료하고 루트로 복사한 vite 설정을 지운다.
- `touch .memory/.done-R2-<A|B|C|D|E>`(커밋 금지). 진행 불가면 `.blocked-R2-<X>`와 이유.
- 저장소 코드(src/, server/, tests/)는 수정하지 않는다.
