  - 2번째 판 종료 후:
    - 기대: coop 레코드 총 4줄 누적
    - 실제: coop 레코드 **총 8줄** 누적
  - 두 기록의 타임스탬프 차이:
    - 1차: `2026-11-07T23:10:52.191Z` (1P), `2026-11-07T23:10:52.192Z` (2P)
    - 2차: `2026-11-07T23:10:52.513Z` (1P), `2026-11-07T23:10:52.514Z` (2P)
    - **정확히 322ms 간격으로 동일한 데이터가 2번 제출됨.**

#### BUG 재현 순서 및 원인 분석
1. **재현 순서**:
   1. 마우스(1P) + 폰(2P) 또는 폰(1P) + 폰(2P)으로 2인 협동 모드 게임 시작.
   2. 게임 진행 중 HP가 0이 되어 `GAMEOVER` 페이즈로 전환.
   3. 서버의 `data/play-records.jsonl` 파일 내용을 확인.
2. **기대 결과**:
   - 해당 판에 대해 1P와 2P의 coop 레코드 각 1개씩 총 2줄만 파일에 기록되어야 함.
3. **실제 결과**:
   - 동일한 내용의 coop 레코드 쌍이 약 300ms 시차를 두고 2번 연속 기록되어 총 4줄이 저장됨.
4. **원인 분석**:
   - `src/components/PCGamePage.tsx` 약 860행 부근:
     ```typescript
     // 100ms마다 실행되는 HUD/게임 루프 타이머 내부
     if (engine.gamePhase === 'GAMEOVER' && gamePhase === 'PLAYING') {
       submitScores(); // 점수 저장 요청
       setPhase('GAMEOVER');
     }
     ```
   - React의 `setPhase('GAMEOVER')` 상태 변경 및 리렌더링이 브라우저/DOM 렌더링 부하로 인해 약 300ms 동안 완료되지 않고 지연됨.
   - `submitScores()`가 이미 호출되었는지를 체크하는 플래그(예: `hasSubmittedScoreRef.current`)가 없어서, 100ms 뒤 다음 인터벌 틱에서도 여전히 `gamePhase === 'PLAYING'` 조건이 참으로 평가되어 `submitScores()`가 한 번 더 실행됨.
