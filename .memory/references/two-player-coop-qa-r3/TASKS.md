# 3차 QA 작업 목록 (Gemini 3.8 Flash, 4명 병렬)

- 지시 공통: [../two-player-coop-qa-checklist.md](../two-player-coop-qa-checklist.md)의 0장(서버·가짜 폰·판정 기준)과 5장 규칙(값·캡처 근거, 눈대중 PASS 금지)을 따른다. **아래 자기 목록만** 확인한다.
- 개발 서버에서 `window.__BEER_DEBUG__.snapshot()`으로 상태·표적 좌표를 읽는다(읽기만).
- 2차 QA 스크립트를 재사용해도 된다: `../two-player-coop-qa-r2/*/scripts/`(특히 가짜 폰 헬퍼 `C-phone-phone/scripts/test-helper.mjs`, 풀플레이 `D-fullplay-mouse/scripts/play-match.mjs`).
- 산출물은 `two-player-coop-qa-r3/<담당>/`에만(캡처, `scripts/`, `report.md`). 저장소 루트·`scripts/`에 파일을 만들지 않는다. 임시 vite 설정은 루트에 두고 끝나면 지운다.
- 저장소 코드(src/, server/, tests/)는 수정·커밋하지 않는다.
- 끝나면 서버 종료 후 `touch .memory/.done-R3-<담당>`(진행 불가면 `.blocked-R3-<담당>` + 이유).
- 가짜 폰의 aimY 부호: 실제 컨트롤러(`src/controller/sensors/GunGripTracker.ts`)의 `invertY` 기본값은 false(폰을 위로 들면 pitch가 커져 aimY 양수 = 화면 위쪽). PC 쪽 `tuning.invertY` 기본값도 확인하고, 2차 C의 "aimY +0.4인데 십자선이 아래" 의심을 Q3 첫머리에서 캡처로 확정한다.

## 시간 측정이 있는 담당(Q3, Q4)의 부하 규칙
4명이 동시에 돌기 때문에, 시간에 민감한 측정(연사 발수, 단발 반응, 보스전 시간) **직전마다** 페이지에서 1초 동안 `requestAnimationFrame` 횟수를 잰다. **30 미만이면 측정하지 말고 30초 기다렸다 다시 잰다**(최대 10분). 측정마다 그 rAF 값과 `uptime` 부하 평균을 함께 기록한다. 10분 안에 30 이상이 안 되면 그 항목은 SKIP(부하) + 값 기록.

## Q1. 2차 수정 확인(시간 측정 없음) — 포트 게임 8821 / 개발 5221
1. 슬롯 이동: 가짜 폰 X를 2P 페어링 → 같은 X를 1P 페어링 → 다시 2P. 매 단계 슬롯 카드 상태(닉네임·연결 표시·마우스 버튼 활성) 캡처. 기대: 한 슬롯에만 X, 빈 슬롯의 마우스 버튼 활성.
2. 남의 카드 사격: 2인(1P 마우스·2P 폰) 무기 선택에서 1P가 2P 카드 중심을 클릭 → `snapshot().selection.done` 변화 없음. 1P 자기 카드 중심 클릭 → 그 카드 선택. 2P 폰도 반대로 같은 확인. 1인 판에서 카드 바깥(카드 반폭 1.2배 밖) 클릭 → 선택 안 됨.
3. 결과 화면 십자선: 1인·2인 결과 화면에서 십자선이 **보이고**, 이름표 없음, 결과 숫자 위에 올려도 숫자가 읽히는지 캡처. 폰 조준으로 "다시 도전하기"를 쏘면 실행.
4. 1024×768 배지·이름표: 2인 무기 선택과 전투에서 카드 배지·십자선 이름표 rect가 화면 안(`left >= 0`, `right <= innerWidth`).
5. 개틀링 콘솔: 개틀링 1인 판 60초 플레이 중 `console.error`·`pageerror` 0건.
6. 시작 직후 단계: 폰 1인으로 가운데 사격 시작 → 카운트다운 끝난 직후(무기 선택 화면) `snapshot().phase === 'PLAYING'`, 그 상태에서 폰 단발로 무기 카드 선택 성공.
7. 2인 난이도 적용(D41): 2인 판 1웨이브 스폰 수(`WAVE 진행도` 분모) 40, 일반 몬스터 `maxHp`가 1인과 같음, 3웨이브 보스 `maxHp` 200(쿨러), 보스 첫 소환 마릿수 8.

## Q2. 2차 C 미완료 항목(시간 측정 없음) — 포트 8822 / 5222
1. 이탈 상태 카드 라운드: 폰+폰 판, 전투 중 2P 폰 끊기 → "혼자 계속하기" → 보상 카드 라운드 발생 시 2P 몫이 즉시 자동 선택되고 1P만 고르면 진행.
2. 무기 선택 중 끊김(결정에 없는 경우, 관찰만): 무기 선택 화면에서 2P 폰 끊기면 무엇이 보이고 어떻게 진행되는지 기록.
3. 결과 화면: 이탈자 칸 "나감" 표시, 폰 조준으로 "다시 도전하기"·"로비로 이동" 각각 동작.
4. 다시 도전 후 같은 1P/2P 구성 유지, 로비로 가면 폰 슬롯은 남음.
5. `data/play-records.jsonl`(임시 폴더)에 판마다 `"mode":"coop"` 정확히 2줄(2차 B에서 중복 의심 — 판 수와 줄 수를 대조).
6. 팀 랭킹 중복: **같은 브라우저(같은 마우스 기기 ID)·같은 폰 기기 ID**로 2인 판을 2번 → 로비·결과의 팀 랭킹에 그 팀이 **한 줄**만(최고 점수). 기기 ID가 다르면 다른 팀으로 여러 줄이 정상이므로, 두 기기 ID를 report에 적는다.

## Q3. 폰 입력(시간 측정 있음, 부하 규칙 적용) — 포트 8823 / 5223
1인 폰(1P 슬롯)과 2인 폰+폰의 2P에서 각각:
1. 단발: 표적 조준 300ms 유지 후 `snapFire` 10회 → 매번 탄약 1 감소, 맞으면 점수 증가. 누락 횟수 기록.
2. 누른 채 연사: 표적 조준 상태로 `rapidFireHold: true`를 30ms 간격 1초 → 탄약 감소 발수(샷건·리볼버·개틀링 각각). 엔진 기준값(1초): 개틀링 약 11, 샷건 약 6, 리볼버 약 7.
3. 피버: 게이지 100에서 `feverTriggered` → `isFeverActive` true, 2초간 점수 증가.
4. 스킬: 재고 1에서 `skillSnapTriggered` → 재고 감소(10회 반복, 실패 횟수).

## Q4. 브라우저 풀플레이 마우스(시간 측정 있음, 부하 규칙 적용) — 포트 8824 / 5224
- 1인 마우스로 샷건·리볼버·개틀링 각 1판, 7웨이브 끝까지(`D-fullplay-mouse/scripts/play-match.mjs` 재사용, 봇은 가장 가까운 착지 표적 조준, 보스전은 부하 먼저).
- 웨이브별 시간·목숨·보스전 시간 기록, 보스전 시간을 엔진 봇 평균(샷건 77/132/85s, 리볼버 109/102/75s, 개틀링 62/86/62s — 웨이브 3/5/7)과 비교.
- 각 웨이브 시작 시 rAF 측정값을 같이 기록(부하로 게임 시간이 느려졌는지 판단용).
