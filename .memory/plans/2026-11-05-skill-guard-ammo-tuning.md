# Plan: 스킬·오비 방패·탄창 조정 + 장전 게이지 링

## Goal
직접 플레이 피드백(스킬이 느리다 / 오비 방패가 올라간 시간이 너무 많다 / 탄창이 빡빡하다 / 장전 중인지 모르겠다)을 반영한다.
측정 가능한 완료 기준:
- 스킬 쿨타임 21/19/16/14초(Lv.1~4), 오비 방패 올림 0.8초·내림 2.4초, 장전 배율 1.2, 탄수 샷건·리볼버 10/10/12/12 · 개틀링 20/25/30/35.
- 값은 `src/shared/gameTuning.ts` 한 곳에서만 바꾼다(샷건·리볼버 탄수 포함).
- PC 조준점 둘레에 장전 진행 게이지 링이 장전 시간 동안 차오르고, 장전이 끝나면 사라진다(피버 중에는 안 나옴).
- 모바일 컨트롤러 쿨타임 초기값이 튜닝 값을 참조한다.
- 피버 중 조준점 회전 링이 실제로 회전한다.
- 코드·문서·README에 남은 "1.2초 / 1.2s / 10발 / 1.5초 / 2배" 같은 하드코딩이 새 값과 일치하거나 값을 참조한다.
- 난이도가 바뀌었으므로 웨이브 기준 시간(parTimeSec)을 다시 재고 보정한다.

근거 문서: [결정 문서](../decisions/2026-11-05-skill-guard-ammo-tuning.md)
추가 범위(사용자 요청, 결정 문서 D06): 모바일 `GunGripPad.tsx` 하드코딩 문구, 모바일 쿨타임 초기값, 랭킹 규칙 버전 3→4, 죽은 `spin` 애니메이션 수정, rapid_reload와 링의 동기화.

## 순서의 이유
- P01 먼저: 수치가 바뀌면 `docs-sync` 테스트(무기 가이드 표)와 여러 테스트의 기대값이 함께 깨진다. 값 변경과 그 값을 가리키는 테스트·표를 같은 Task에서 고쳐야 Task마다 `npm test`가 통과한다.
- P02는 수치와 독립이라 P01 뒤에 둔다(장전 시간이 확정돼야 링 속도를 눈으로 확인할 수 있다).
- P03은 마지막: 방패·탄수·쿨타임이 모두 클리어 시간에 영향을 주므로 기준 시간(parTimeSec)은 모든 값이 확정된 뒤 잰다.

## 선행 상태 / 충돌
- 이전 계획 `2026-11-05-score-differentiation`의 P03-T04(사람 직접 플레이)가 대기 중이다. 이 계획이 난이도 값을 바꾸므로 그 플레이 확인은 **이 계획의 P03-T02와 합쳐서** 한 번에 한다.
