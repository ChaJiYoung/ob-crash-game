### 최종 수치 시뮬레이션(무기·봇별 60판, 샷건 / 리볼버 / 개틀링 클리어율 %)

| 봇 | 클리어율 |
|---|---|
| 정확(탭) | 98 / 95 / 100 |
| 보통(탭) | 83 / 77 / 80 |
| 부정확(탭) | 67 / 52 / 52 |
| 아주 부정확(탭) | 32 / 22 / 17 |
| 몬스터 따라가며 누른 채 사격 | 45 / 25 / 68 |

- 보통 봇 한 판 약 3~3.5분, 피버 간격 20~29초, 판당 카드 약 7~8장, 스킬 약 10~11회, 무기 MAX 도달 48~55%
- 오차는 ±13%p 정도. 봇은 밀리지 않으면 거의 안 맞아 이긴 판 체력이 평균 3.7~5칸 남는다. "아슬아슬함"은 봇으로 판단할 수 없다.

## D01. 요격 피드백: 배너 제거, 몬스터처럼 폭발 [사용자]
- **Chosen**: `INTERCEPTED` 배너(`interceptedBannerKey` 상태와 JSX)를 제거한다. 요격한 투사체는 몬스터처럼 파티클과 함께 터지고, 요격음과 점수는 유지한다.
- **Rationale**: 사용자는 별도 문구 없이 터지는 피드백을 원한다. 배너가 계속 떠 있던 원인은 리셋 코드가 없고 `@keyframes fadeUp`도 정의되지 않은 것이다. 이 배너는 적이 방어선을 돌파할 때가 아니라 플레이어가 투사체를 맞혔을 때 뜬다. 실제 획득 점수도 표시된 +50이 아니다(`killBonusScore` 80 + 판정 점수).
- **확인 필요**: 처치 이펙트는 React effect 안에서 메시를 찾아 실행한다. 렌더 루프가 메시를 먼저 지우면 폭발이 생략될 수 있으므로 D06의 직접 호출로 보장한다.

## D02. 사격 번쩍임: 총구 플래시 크기 버그 수정 [자동]
- **Chosen**: `ParticleEffects3D.ts:765`가 플래시 크기를 절대값 1.0~1.5로 덮어쓰는 버그를 고쳐, `spawnTracerBeam`에서 정한 반경을 기준으로 애니메이션한다. 투명도(`:764`)도 낮춘다. 피버·위기 조명의 고주파 깜빡임은 완화한다.
- **Rationale**: 의도한 반경은 0.11~0.16인데 실제로는 약 10배인 구체가 카메라 1.63m 앞에 생겨 한 발마다 화면 대부분을 덮었다(스크린샷으로 확인). 이전 계획의 `flashRadius`·`opacity` 수정은 매 프레임 덮어써져 효과가 없고, `applyTargetHitFlash3D`의 발광 코드는 존재하지 않는다.

## D03. 그래픽 설정: 블룸 끄기 + 렌더링 300만 픽셀 상한 [사용자]
- **Chosen**: `UnrealBloomPass`를 제거한다. 렌더 해상도는 DPR이 아니라 총 픽셀 수(300만)를 기준으로 제한한다. `pixelRatio = min(dpr, sqrt(3,000,000 / (w * h)))`
- **Rationale**: 3440×1440에서 FPS가 37에서 93으로 오른다. 울트라와이드는 이미 DPR 1이라 DPR 상한으로는 효과가 없다. 라벨은 더 또렷해지고, 거품과 배경의 빛 번짐은 사라진다.
- **유지**: 포인트 라이트 3개. 끄는 효과가 8%(93 → 100)로 작아 이번에는 바꾸지 않는다.

## D04. 멈춤 제거: 셰이더·텍스처 재생성 차단 [자동]
- **Chosen**:
  1. 몬스터 본체처럼 인스턴스마다 만드는 머티리얼의 셰이더가 해제되지 않게 한다. 캐시 공유 또는 영구 앵커 머티리얼을 쓴다. 프리즈 틴트는 현재 동작을 유지한다.
  2. 셰이더 예열 뒤 샘플을 dispose하지 않게 하고, 카드·보스·대왕까지 예열한다.
  3. `disposeSceneGroup`이 공유 라벨 텍스처를 폐기하지 않게 `isShared`를 지정한다.
  4. 카드 텍스처를 종류별로 캐시하고 재사용한다.
- **Rationale**: 같은 재질의 몬스터가 필드에서 모두 사라지면 셰이더가 삭제되고, 다음 스폰 때 다시 만들며 0.6~2초 멈춘다. `GameCanvas3D.tsx:317`은 예열 직후 샘플을 dispose해 예열 효과를 없앤다. 처치마다 라벨 텍스처도 다시 업로드된다.

## D05. 타격 이펙트 약 30%로 축소 + 묶어 그리기 [사용자]
- **Chosen**: 파티클 수를 피격 18→5, 처치 32→10, 보스 처치 48→15로 줄인다. 병 파괴 파편(16+14)도 같은 비율로 줄인다. 캔 물방울 8개를 제거하고, 샷건 탄환은 단순한 메시로 바꾼다. 스킬 이펙트 모양은 유지한다. 파티클은 `InstancedMesh`로 묶어 그린다. [자동: 묶어 그리기, 병 파편 비율]
- **Rationale**: FPS 증가는 3~7%로 작지만, 프레임당 그리기 요청이 397회에서 200회로 줄고 화면이 깔끔해진다. 파티클을 완전히 없애도 FPS 차이가 거의 없어 타격감을 남겼다.

## D06. HUD: 블러·그림자 제거 + 갱신 구조 개선 [자동]
- **Chosen**: `backdropFilter`, `filter: drop-shadow`, 그림자를 제거하고 어두운 불투명 패널로 바꾼다. 50ms·32ms 주기로 페이지 전체를 리렌더하지 않도록 값이 바뀔 때만 갱신하고, HP바는 직접 DOM으로 갱신한다. 사격 이펙트는 React state 대신 캔버스 핸들로 직접 호출한다.
- **Rationale**: 프레임이 튀는 주요 원인이 HUD 합성 비용이었다. 초당 약 25~50회 커밋을 절반 이하로 줄이면 메인 스레드 사용이 약 700ms에서 400ms(1초당)로 줄어 입력 반응에 여유가 생긴다.

## D07. 카드 선택 중 오발 방지와 전체 정지 [사용자 + 자동]
- **Chosen [사용자]**: 누르고 있던 입력은 무시하고, 뗐다가 새로 누른 한 발로만 선택한다. 기존 0.8초 입력 잠금을 유지하고, 카드 밖 사격은 탄약을 소모하지 않는다.
- **Chosen [자동]**: 모든 발사가 지나는 `engine.shootAt`에서 막는다. 호출부에 입력 종류(`새 입력`/`연사`)를 전달한다. 카드 선택 중에는 피버, 버프, 스킬 쿨다운, 재장전 시간을 모두 멈추고, PC 키의 스킬·피버 발동도 막는다. 웨이브 클리어 카드에도 같은 규칙을 적용한다.
- **Rationale**: 자동 발사 경로가 모바일 연타, 피버 자동 발사, 마우스 홀드(`GameCanvas3D.tsx:377`)로 3개이고, 이전 계획은 마우스 홀드를 빠뜨렸다. `BeerCrusherEngine.ts:860-861`이 정지 검사보다 먼저 실행되어 카드 선택 중에도 쿨다운과 피버 시간이 흐른다.

## D08. 카드 풀 9종과 등장 규칙 [사용자 + 자동]
- **Chosen [사용자]**: 카드 4종을 추가해 총 9종으로 한다. 수치는 사용자 요청으로 낮췄다.
  - 공격력 +10%(최대 3회)
  - 스킬 쿨다운 -10%(최대 3회)
  - 피버 지속시간 +0.5초(최대 3회)
  - 명중 판정 범위 +5%(최대 2회)
- **Chosen [자동]**:
  - 매번 중복 없이 3장을 뽑고, 무기 카드도 다른 카드와 같은 확률로 나온다.
  - 무기 Lv.4와 웨이브 상한(D09), 행운 3회, 장전 3회에 도달하면 해당 카드를 제외한다. 피버가 찼거나 발동 중이면 피버 부스터를 제외한다.
  - 피버 부스터를 설명대로 실제 +50% 충전으로 고친다.
  - 초고속 장전의 설명을 실제 값인 20%로 고친다.
- **Chosen [사용자]**: 수리 카드는 체력 +2 회복으로 약화한다. 최대 체력은 늘리지 않고, 체력이 가득하면 풀에서 제외한다.
- **Rationale**: 카드가 5종이면 무기와 행운이 MAX일 때 같은 3장만 반복된다. 이전 D04가 말한 공격력·쿨다운 카드는 코드에 없었다.

## D09. 게이지 밸런스: 중간안 + 무기 MAX 지연 [사용자]
- **Chosen**:
  - 피버 충전: 처치 `KILL_FEVER_DELTA` 4, PERFECT `feverDelta` 2
  - 금색 캔: 피버 +30%, 스킬 1회 충전(현재는 피버 100%, 스킬 완충)
  - 스킬 쿨다운 Lv.1~4: 35 / 31 / 27 / 23초
  - 무기 레벨 상한: 1웨이브 Lv.2, 2~4웨이브 Lv.3, 5웨이브부터 MAX
- **Rationale**: 금색 캔이 웨이브마다 피버를 채워, 충전량만 낮추면 첫 피버가 12초로 고정된다. 지금은 1웨이브에서 카드 3장이 나와 무기가 MAX에 이른다. 확률만 낮추면 운이 좋을 때 여전히 빠르므로 웨이브 상한을 둔다.
- **카드 등장**: 웨이브 클리어 카드에 더해, 4웨이브 22킬과 6웨이브 26킬에 중간 카드를 준다(판당 최대 8장, 약 23~26초에 한 장). 다른 웨이브에는 중간 카드가 없다.

## D10. 연타 방지와 무기 균형 [사용자]
- **Chosen**:
  - **판정 범위**: 전 무기 x0.75, 화면비 보정 추가
  - **판정별 피해 배율**: PERFECT 2.0 / GREAT 1.0 / GOOD 0.5
  - **연사와 장전(전 무기)**: 발사 간격 x0.7(약 1.4배 빠름), 장전 시간 x2
  - **누른 채 쏘는 연사**: 피해 x0.6, 발사 간격 x0.7 추가. 개틀링은 피해 x0.85, 발사 간격 x0.85 추가. 탭 사격과 피버 자동 발사는 감소 없음
  - **샷건**: 판정 배율 1.55 → 1.40, 피해 x1.2
  - **리볼버**: 추가 변경 없음
  - **개틀링**: 탄창 Lv.1~4 13 / 15 / 20 / 25, 피해 x2
  - **몬스터 기본 능력치와 MISS 페널티**: 변경하지 않는다.
  - 판정, 연사, 장전, 피해 수치는 한 파일의 상수로 모아 플레이하면서 바로 조정한다.
- **Rationale**:
  - `BeerCrusherEngine.ts:1172`의 `hitRadiusM * 2.8` 때문에 16:9, 14m 기준 판정이 캔보다 가로 약 10배, 세로 약 4배 크다. 가로는 화면비를 반영하지 않아 울트라와이드에서 더 넓다.
  - 판정만 좁혀서는 막 쏘기를 막지 못한다. 처음 쓴 봇은 몬스터를 보지 않아 비현실적이었고, 몬스터를 따라가며 쏘는 봇으로 다시 재니 x0.6에서도 리볼버·개틀링이 100% 깼다.
  - 빗나감 패널티(과열, 탄약 추가 소모)는 리볼버·개틀링 연타 클리어율을 사실상 낮추지 못했다.
  - 연사를 빠르게 하고 장전을 늘리면 빗나간 탄이 긴 장전으로 이어져 손해가 생긴다. 탄창이 큰 개틀링은 탄창도 줄여야 효과가 난다.
  - 누른 채 쏘는 연사의 피해를 낮추면 처음으로 연타가 조준보다 불리해진다. 연사 속도를 더 올리는 것은 클리어율에 거의 영향이 없어 손맛 기준으로 정했다.
  - 사용자는 무기별 클리어 확률이 비슷하고, 잘 맞힐수록 유리하길 원한다. 피해 격차를 넓히면 판정 범위를 더 좁히지 않아도 실력 차이가 커진다.
- **주의**:
  - 빠른 탭 연타는 제한하지 않는다. 봇 기준 탭은 강하지만 사람은 오래 지속하기 어렵고 자이로 조준도 흔들린다. 플레이 후 너무 쉬우면 "발사 간격 0.35초 미만은 연사 처리" 규칙을 검토한다. 이 규칙을 시험했을 때 정조준 봇도 37~48%로 떨어졌다.
  - 개틀링은 연사 무기라 누른 채 쏴도 60~68%로 다른 무기보다 잘 깬다. 직접 플레이로 판단한다.
  - 장전은 2~3배 사이에서 조정한다. 3배에서는 샷건·리볼버 클리어율이 3~7%로 급락했다.
  - 실제 폰 자이로에서 빡빡할 수 있어 플레이 검증이 필수다.

## D12. 보스전 구조 [사용자 + 자동]
- **Chosen [사용자]**:
  - 구성: 냉각기 1대 → 2대 → 2대 + 대왕
  - 진행: 미니웨이브를 먼저 상대한 뒤 경고 연출과 함께 보스가 나온다. 보스전 중에는 일반 스폰을 멈춘다. 질문 8은 "보스만 나오면 재미없다"는 답을 근거로 이 안으로 확정하고 알렸다.
  - 패턴: 냉각기 1대는 좌우 이동, 2대는 교차 이동과 투사체 번갈아 발사, 대왕은 쉴드(무적)이며 냉각기나 소환 부하를 잡아야 풀린다.
  - 돌진 없음: 보스는 방어선으로 돌진하지 않고 중간중간 부하를 소환해 압박한다.
  - 소환 구성: 앞서 나온 몬스터를 종합하되 보스전마다 한 종씩 늘린다. 첫 보스 3종(오비, 카스 라이트, 한맥), 두 번째 보스 4종(필굿, 오비, 한맥, 병맥주), 세 번째 보스 5종 전부.
  - 공략: 보스 몸통 타격으로는 피버가 차지 않는다. 부하를 잡아 피버와 아이템을 모아야 깨기 쉽다. 스킬 쿨다운 보너스는 넣지 않는다.
- **Chosen [자동]**:
  - 중간 보스를 처치하면 보상 카드 후 다음 웨이브로 간다. 마지막 보스전은 전부 잡아야 승리한다(`:1183` 수정).
  - 보스는 좌우로 벌려 배치한다(`:1120-1138`).
  - 체력 표시는 모든 보스를 보여 준다(`:580`, `PCGamePage.tsx:776`).
  - 소환 타이머는 보스전 전체에서 하나를 공유한다.
  - 보스 판정은 모델 크기에 맞게 따로 계수를 둔다.
  - 보스는 넉백 면역으로 한다. 지금은 샷건 넉백(`:1400-1401`)이 보스를 밀어 소환 거리 12.5m(`:1034`) 안으로 못 들어오게 한다. 대왕 쉴드까지 있으면 부하가 나오지 않아 판이 끝나지 않는다.
- **[초안] 수치**(시뮬레이션에 사용한 값):
  - 체력: 냉각기 1대 40, 2대 각 35, 마지막 냉각기 각 45 + 대왕 110
  - 대왕: 모델 1.5배, 판정 반경 1.5배
  - 보스 판정: 공통 범위에 x0.6 추가, 등장 거리 16m
  - 소환: 8초마다 4마리, 필드의 부하가 7마리 미만일 때
  - 쉴드: 대왕 등장 시와 체력 2/3, 1/3에서 켜짐. 부하 6마리 처치 또는 냉각기 처치로 해제
  - 소환 부하 아이템 드롭률: 20%(현재 처치당 4%)
  - 이동: 냉각기 1대 좌우 진폭 0.32rad, 2대 교차 0.34rad, 대왕 0.12rad
- **재조정 필요**: 최종 시뮬레이션에서 보스전 시간이 3웨이브 3~12초, 5웨이브 9~18초, 7웨이브 29~51초로 나왔다. 특히 샷건의 첫 보스전이 3~5초로 너무 짧아, 계획 단계에서 보스 체력과 샷건의 보스 피해를 다시 맞춘다. 최종 시뮬레이션에서는 시간 초과가 없었지만, 직전 측정에서 개틀링 판의 약 3%에서 나왔으므로 함께 확인한다.
- **Rationale**: 지금 보스는 항상 정중앙에 나오고 10m 앞에 멈추며, 판정 반경이 화면 폭의 약 58%라 가운데 연타만으로 잡힌다. 사용자는 부하에게서 얻은 피버와 아이템으로 보스를 깨는 흐름을 원한다.

## D14. 완료 기준 [자동]
- **성능**: 고정 60fps 대신 모니터 주사율을 기준으로 한다(이 맥의 외장 모니터는 50Hz).
  - 일반 전투에서 프레임 p95가 60Hz 16.7ms, 50Hz 20ms 이내
  - 게임 시작 후 `linkProgram` 0회, 처치 시 텍스처 업로드 0회
  - 실제 모니터 환경에서 재측정(수직 동기화 켬)
- **밸런스(봇 기준)**: `simulate-current-decisions.ts`로 확인한다.
  - 보통 봇: 세 무기 모두 약 70~85%, 무기 간 차이 15%p 이내
  - 정확 봇 90% 이상, 아주 부정확 봇 40% 이하
  - 화면 전체 훑기 거의 0%, 샷건·리볼버의 누른 채 사격은 조준 보통보다 낮을 것
  - 보스전이 끝나지 않는 판(시간 초과) 없음
  - 한 판 약 3~3.5분, 피버 약 20~30초 간격, 판당 카드 약 8장
- **최종 판단(사람)**: 수치 통과 후 폰 자이로와 마우스로 직접 플레이한다. 처음 하는 사람이 3판 중 1~2판을 깨고, 이겼을 때 체력이 1~3칸 남는 정도를 목표로 상수를 조정한다.
