# Decisions: 판별 플레이 기록 저장

- Date: 2026-11-05
- Status: Confirmed

## D01. 끝난 모든 판을 분석용으로 저장한다
- **Chosen**: 게임오버와 승리로 끝난 모든 판을 서버 파일에 저장한다. 화면과 랭킹보드는 바꾸지 않는다.
- **Rationale**: (사용자 선택, 화면 변경 없음은 기록 항목에 한함. 랭킹 배치는 D05) 점수뿐 아니라 점수 산정 정보를 남겨 난이도와 무기 비교에 쓴다. 실패한 판도 있어야 난이도를 판단할 수 있다.

## D02. 랭킹 파일과 분리한 JSONL 파일에 쓴다
- **Chosen**: `data/play-records.jsonl`에 판마다 JSON 한 줄을 덧붙인다(`data/`는 이미 git에서 제외). `players.json`에는 넣지 않는다.
- **Rationale**: (코드 기반 확정) `players.json`은 규칙 버전이 바뀌면 점수가 초기화되고 저장 때마다 파일 전체를 다시 쓴다. 덧붙이기 파일은 초기화 영향이 없고 판이 쌓여도 느려지지 않는다.

## D03. 저장 항목
- **Chosen**:
  - 식별: `playedAt`, `deviceId`, `nickname`, `rulesetVersion`
  - 결과: `outcome`(`GAMEOVER`|`VICTORY`), `waveReached`, `livesLeft`, `durationSec`(게임 시계)
  - 점수: `totalScore`, `baseScore`, `timeBonus`, `precisionBonus`, `maxCombo`
  - 처치: `kills`(판 전체), `waves`(웨이브별 `{ wave, seconds, bonus }`)
  - 판정: `shots`(`PERFECT`, `GREAT`, `GOOD`, `MISS` 수), `accuracy`(`getPrecisionStats().ratio`)
  - 무기: `weaponKind`, `weaponLevel`
  - 패시브: `cardStacks`(`damage_up`, `skill_cooldown`, `fever_extend`, `hit_zone_up`), `maxAmmoBonus`는 있으면 포함
- **Rationale**: (사용자 요청 + 코드 기반 확정) "페시브 레벨"은 보상 카드 누적으로 해석했다(사용자 이의 없음). 판 전체 처치 수와 웨이브별 기록은 엔진에 없어 새로 모은다(`killedInWave`는 웨이브마다 초기화, `lastWaveClear`는 마지막 값만 남음).

## D04. 전송과 오류 처리
- **Chosen**: `GAME_SCORE_SUBMIT`에 선택 필드 `stats`를 추가한다. 서버는 점수를 먼저 기록하고 기록 저장은 별도로 시도해, 파일 쓰기가 실패해도 랭킹 저장을 막지 않고 오류만 로그에 남긴다. 규칙 버전이 달라 거절된 점수는 기록하지 않는다. `stats`가 숫자·길이 형식에 맞지 않으면 그 기록만 건너뛴다.
- **Rationale**: (코드 기반 확정) 기존 제출 경로를 재사용하면 점수와 기록이 같은 시점에 남는다. 클라이언트가 보낸 값이므로 파일을 오염시키지 않게 검증한다.

## D05. 결과 화면 옆에 랭킹을 둔다
- **Chosen**: 게임이 끝나면 결과 패널과 명예의 전당 TOP 5를 좌우로 나란히 보여 준다. 기록이 없으면 빈 칸 대신 안내 문구를 띄운다.
- **Rationale**: (사용자 요청) 랭킹은 저장되어 있었고 메인에서 보고 나서야 확인했다. 지금도 결과 화면 맨 아래에 목록이 있지만 세로로 쌓여 잘 보이지 않는다. 데이터는 이미 `rankings`로 전달되므로 레이아웃만 바꾼다.

## D06. 랭킹은 판별 TOP 5로 바꾼다
- **Chosen**: 플레이어별 최고 점수 대신 **판별 점수 상위 5개**를 보여 준다. 같은 사람이 여러 줄 나올 수 있다. 한 줄에 순위, 닉네임, 점수, 도달 스테이지, 무기를 표시한다. 결과 화면과 로비 보드에 모두 적용한다.
- **Rationale**: (사용자 요청) 무기와 스테이지는 판마다 다르므로 판 단위 기록과 맞는다.
- **코드 기반 확정**:
  - 현재 규칙 버전의 `data/play-records.jsonl` 기록에서 계산하므로 규칙이 바뀌면 랭킹은 새로 시작하고 기록 파일은 남는다. 서버 시작 때 읽어 메모리에 상위 5개를 유지한다.
  - 기록이 없던 이전 판은 무기와 스테이지를 몰라 보드에 나오지 않는다. 지금 보드의 두둥 21,395점도 사라지며 보드는 비어서 시작한다.
  - 같은 점수면 먼저 세운 기록이 위다. `players.json`의 최고 점수와 신기록 판정은 그대로 둔다.

## D07. 결과 화면에 최대 콤보와 처치 수를 따로 보여 준다
- **Chosen**: '누적 격파 (KILL)' 칸은 실제 처치 수(`stats.kills`)를 표시하고 '최대 콤보' 칸을 추가한다. 최대 콤보는 기록에도 저장한다(D03).
- **Rationale**: (사용자 요청 "최대콤보값도 있으면 좋겠다") 지금 KILL 칸이 콤보 값을 잘못 보여 준다.

## 범위 밖 (사용자에게 보고함)
- 서버 연결이 끊긴 채 판이 끝나면 점수와 기록이 모두 조용히 버려진다(`submitScore`).
- 일시정지 메뉴의 다시시작(다른 결정 문서)처럼 중간에 포기한 판은 저장 대상이 아니다.
- 기록 조회 화면이나 내보내기는 없다. 파일을 직접 분석한다.
- `deviceId`와 닉네임이 들어가므로 파일을 외부에 공유할 때 주의한다.

## D08. 저레벨 클리어 보너스 (2026-11-06)
- **Chosen**: 승리한 판에서 끝날 때의 무기 레벨에 따라 기본 점수에 배율을 곱한다(Lv.1 ×1.2, Lv.2 ×1.1, Lv.3 ×1.05, MAX ×1.0). `RANKING_RULESET_VERSION`을 5로 올린다.
- **Rationale**: (사용자 승인) 레벨업 카드 선택에 위험과 보상을 만든다. 레벨업 카드를 피하는 보통 봇의 클리어율은 샷건 75%, 리볼버 67%, 개틀링 82%(각 100판)로, 낮은 레벨 클리어가 가능하다.
