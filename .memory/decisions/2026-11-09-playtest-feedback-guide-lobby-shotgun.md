# Decisions: 플레이 피드백 반영 (가이드·로비·샷건 스킬/퍼짐)

- Date: 2026-11-09
- Status: Confirmed
- Trigger: 외부 플레이 피드백 5건. ① 가이드 화면이 글자뿐이라 보기 어렵다 ② 처음에 1P 모바일이 기본이면 좋겠다 ③ 로비에서 처음에 뭘 해야 할지 안내가 부족하다 ④ 샷건 스킬이 너무 짧다(뚫어뻥이 박혀 있다가 터지는 방식 제안) ⑤ 샷건이 "샷건" 같지 않다(탄이 더 멀리 퍼졌으면).
- 관련 결정: [2026-11-07-weapon-balance](./2026-11-07-weapon-balance.md), [2026-11-07-two-player-coop](./2026-11-07-two-player-coop.md), [2026-11-06-lobby-controls-hint](./2026-11-06-lobby-controls-hint.md)

## A. 샷건 스킬 (사방 뚫어뻥 폭풍) 재설계

## D01. 스킬 방식: 박힘 → 기절 → 폭발
- **Chosen**: 스킬을 쓰면 뚫어뻥이 몬스터에 박혀 기절시키고, **기절이 끝나는 순간 폭발해 피해**를 준다. 박히는 순간의 즉시 피해는 없다.
- **Rationale**: 사용자가 "뚫어뻥이 박혀 있다가 시간 지나면 터지는" 아이디어를 선택(사용자 선택). 지금은 즉시 피해와 짧은 기절(1.0~2.0초)이 전부라 존재감이 약하다.

## D02. 박히는 대상: 방어선에 가까운 순서로 레벨별 마릿수 상한
- **Chosen**: 방어선(바)에 가까운 일반 몬스터부터 **Lv1~4 최대 4 / 5 / 6 / 8마리**에 박힌다. 몬스터가 상한보다 적으면 전원이 박힌다. 폭발은 박힌 몬스터에게만 준다(주변 피해 없음). 이미 박힌 몬스터는 대상에서 빼고 다음으로 가까운 몬스터를 고른다(코드 확인 후 자동 확정, 2인팟에서 두 플레이어가 겹치는 경우 포함).
- **Rationale**: 사용자가 "샷건은 모든 애한테 피해는 아니지 않나"라고 지적했다(사용자 선택). 지금 연출은 뚫어뻥이 몬스터 쪽으로 유도돼 날아가 사실상 전원이 박히므로, 마릿수 상한이 있어야 "전원이 아님"이 성립한다. 조준 기반(십자선 근처만)은 모바일 센서에서 빗나갈 위험이 커 제외했다.

## D03. 수치: 기절·폭발 피해
- **Chosen**: 기절 **2.0 / 2.2 / 2.5 / 3.0초**(사용자 지정), 박힌 일반 몬스터 폭발 피해 **0.7 / 0.8 / 0.9 / 1.0**(리볼버 스킬 약 1.05~1.21보다 낮게, 사용자 요청). 쿨다운은 기존 공통 표(21 / 19 / 16 / 14초)와 최대 스톡 2를 그대로 쓴다.
- **Rationale**: 게틀링 "밀려났다 돌아오는" 시간(약 1.5~2.5초)보다 조금 길게, 현재 기절(1.0~2.0초)의 약 1.5~2배로 잡았다. 샷건 평타가 이미 가장 세서(탄창 총 피해 Lv4 기준 샷건 69, 게틀링 37.5, 리볼버 14.5) 스킬은 피해보다 제어 도구로 둔다.

## D04. 보스
- **Chosen**: 보스는 **지금처럼 즉시 피해만** 받는다(4 / 5 / 6 / 6). 박힘·기절·폭발은 없고, 일반 몬스터 상한에도 포함되지 않는다.
- **Rationale**: 사용자 선택. 보스 체력 60에 기절을 걸면 균형이 크게 흔들리고, 보스 처리 코드(`bossClearUntilMs` 등)를 건드릴 필요가 없다.

## B. 샷건 평타 퍼짐 (추가 명중)

## D05. 한 발에 주변 몬스터도 맞는다
- **Chosen**: 십자선에 가장 가까운 몬스터(주 대상)에게 기존처럼 피해를 주고, **십자선 주변에서 가까운 순서로 추가 몬스터 2 / 2 / 3 / 3마리**에게 낮은 피해를 준다. 추가 대상은 **십자선 중심, 화면 거리 기준**으로 고른다(D17). 보스는 추가 명중 대상에서 제외하고 주 대상일 때만 피해를 받는다. 누르고 쏘기 감점(`holdDamageByWeapon.shotgun` 0.6)과 판정·피버·파워샷 배율은 추가 명중에도 같은 방식으로 적용한다(자동 확정). 연출 퍼짐도 지금의 약 2배로 넓히고 추가 명중 대상 쪽으로도 탄이 날아가게 한다.
- **Rationale**: 사용자가 "샷건 특색이 덜하다"는 평에 대해 다중 명중 방식을 선택. 지금은 탄 3~6발이 그려지기만 하고 판정은 한 줄(탄 수는 피해 계산의 곱 `pelletCount × damagePerHit`에만 쓰임)이라 퍼져 보여도 퍼진 탄이 맞지 않는다.

## D06. 추가 명중 피해 비율: 레벨별 상승
- **Chosen**: 주 대상 피해 대비 **10 / 15 / 20 / 25%**(Lv1~4). 추가 대상 1마리당 피해는 평타 낮춤(D07) 후 약 0.11 / 0.24 / 0.50 / 0.90.
- **Rationale**: 사용자가 "주변 데미지 비율도 레벨별로 오르게"를 요청했다. 이미 센 Lv3~4가 서열을 넘지 않도록 낮은 쪽에서 시작한다(사용자 선택: 가).

## D07. 평타 낮춤: 샷건 피해 스케일 1.2 → 1.0
- **Chosen**: `GAME_TUNING.weaponDamageScale.shotgun`을 1.2에서 **1.0**으로 낮춘다. 한 발 피해(GREAT, 탄 수 곱 포함)는 1.26 / 1.92 / 3.00 / 4.32에서 **1.05 / 1.60 / 2.50 / 3.60**이 된다. 뭉쳤을 때 한 발 최대는 1.26 / 2.08 / 4.00 / 6.30.
- **Rationale**: 사용자가 "퍼짐이 없던 무기에 추가 명중을 더하니 평타를 낮춰야 한다"고 지적했다(사용자 요청). Lv1은 1.05라 GREAT 한 발이 체력 1짜리를 죽이는 **1레벨 원샷 규칙**(D02 of weapon-balance)이 유지된다. 이 규칙 때문에 Lv1을 더 낮출 수 없다.

## D08. 균형 목표와 튜닝 규칙
- **Chosen**: 목표는 **봇 클리어율 게틀링(68%) < 샷건 < 리볼버(70%)**. D05~D07 값은 출발값이고, 구현 뒤 `playtest-bot`/`simulate-balance-bundles`로 **80판** 측정한다. 68% 미만이면 추가 명중 비율을 한 단계 올리고(10/15/20/25 → 15/20/25/30), 70% 초과면 한 단계 내린다(→ 5/10/15/20). 그래도 안 맞으면 폭발 피해(D03)와 퍼짐 반경을 조정한다. 계획 단계에 측정·튜닝 Task를 둔다.
- **Rationale**: 지금 측정 서열은 샷건 63% < 게틀링 68% < 리볼버 70%로 샷건이 가장 약하다(weapon-balance D07). 탄창 총 피해 같은 이론치는 과잉 피해 낭비와 조준 실패를 반영하지 못해 서열이 실제와 다르다. 올리는 쪽이 내리는 쪽보다 부담이 적어 낮은 값에서 시작한다.

## C. 로비·가이드

## D09. 1P 모바일 기본값 + 마지막 입력 방식 기억
- **Chosen**: 로비가 열릴 때 **1P 슬롯은 마지막에 쓴 입력 방식**으로 미리 선택된다. 기록이 없거나 값이 이상하면 `mobile`(QR이 바로 보임). **2P 슬롯은 항상 비어 있게** 시작한다. 저장은 `localStorage`(읽기·쓰기 모두 `try/catch`), 기기 ID 저장(`deviceIdentity.ts`)과 같은 방식. 마우스를 기억해 둔 경우에는 버튼을 직접 누른 것과 같은 경로(`handleChooseInput` → 서버 `LOOKUP_LOCAL_PLAYER` 조회)를 탄다. 이미 등록된 기기는 닉네임 입력 없이 바로 준비 완료가 되고, 처음 보는 기기는 닉네임 입력 폼이 뜬다(코드 확인으로 정정: 기존 동작이 이미 "조회 성공 시 자동 준비"이고 2인팟 D15와 같다). 판 종료 후 "로비로"·일시정지에서 로비로 돌아올 때도 같은 기본값을 적용한다.
- **Rationale**: 사용자 선택(마지막 방식 기억). 지금은 `createInitialSlots`가 두 슬롯 모두 `input: null`이라 QR을 보려면 먼저 📱 버튼을 눌러야 한다.

## D10. 로비 "지금 할 일" 배너 + 단계 표시
- **Chosen**: 로비 위쪽에 ① 폰으로 QR 스캔 → ② 영점 조정 → ③ 쏴서 시작의 3단계 줄을 두고, **슬롯 상태에 따라 현재 단계를 강조**하며 지금 할 일 한 문장을 크게 보여 준다(예: "폰으로 QR을 스캔하세요", "폰을 화면 쪽으로 들고 영점을 맞추세요", "준비 완료! 화면을 향해 쏘면 시작합니다"). 마우스 슬롯이면 "닉네임 입력 → 클릭으로 시작"으로 바뀐다. 2인 연결 시에는 아직 준비되지 않은 쪽 기준으로 문장을 정한다(시작 조건 `StartGate`에 맞춤, 코드 확인 후 자동 확정). 새 서버 데이터는 필요 없고 기존 슬롯 상태(`SlotState`)에서 계산한다.
- **Rationale**: 사용자 선택. 슬롯 카드에 상태 문구는 있지만 다음에 할 일을 알려 주는 곳이 없다.

## D11. 가이드 모달: 카드화 + 한 줄 요약 + 자세히 접기
- **Chosen**: 기존 5개 탭(무기·몬스터·카드·아이템·협동) 구조는 유지하고, 각 항목(무기·몬스터·카드·아이템)을 **카드**로 만든다. 카드 위쪽에 큰 아이콘과 "한 줄 요약"(예: "한 발이 강한 근접 산탄"), 수치는 칩이나 막대로 보여 주고, 긴 설명은 "자세히 보기"를 눌러야 펼친다. "시작하기" 탭 신설과 이미지 캡처 삽입은 이번에 하지 않는다.
- **Rationale**: 사용자 선택. 지금은 한 항목의 수치와 설명이 한 줄 불릿에 모두 들어가 눈에 안 들어온다. 이미지는 무기·스킬이 바뀔 때마다 다시 만들어야 해서 제외했다. 시작 안내는 D10 로비 배너가 맡는다.

## D12. 가이드 문구·수치는 새 값에서 자동으로 읽는다
- **Chosen**: 샷건 스킬과 평타 설명(`GuideModal`의 샷건 항목, `weaponPerformanceText`)은 새 튜닝 값(마릿수, 기절, 폭발 피해, 추가 명중 마릿수·비율)에서 계산해 쓴다. 손으로 적은 숫자("12~22개", "1.0~2.0초")는 남기지 않는다. `docs/무기_및_스킬_가이드.md`도 새 값으로 고친다(자동 확정).
- **Rationale**: 가이드를 바꾸는 이번 작업이 같은 항목을 다루고, 값을 직접 적어 두면 튜닝(D08) 때마다 어긋난다.

## D13. 테스트
- **Chosen**: 샷건 스킬(박힘 상한·방어선 우선·기절 후 폭발·보스 제외), 추가 명중(마릿수·비율·보스 제외·중복 피해 방지), 1레벨 원샷 규칙 유지, 1P 입력 방식 기억(저장소 접근 실패 포함), 로비 배너 단계 문구, 가이드 카드 렌더를 `tests/`에 추가·수정한다. 샷건 값을 고정한 기존 테스트(`game-tuning`, `shared-protocol`, `engine-judgment-and-spawn`)는 새 값으로 고친다(자동 확정).
- **Rationale**: 이 영역은 이미 같은 테스트 파일들이 값을 고정해 두고 있다.

## D. 요청 밖 발견 항목 정리 (2026-11-09 추가 인터뷰)

## D14. 샷건 스킬 수치를 `GAME_TUNING`으로 옮긴다
- **Chosen**: `GAME_TUNING.skills.plunger`를 새로 만들어 마릿수 상한, 기절 ms, 폭발 피해, 보스 피해, 연출용 뚫어뻥 개수를 둔다. `applyWeaponTuning`이 리볼버·게틀링처럼 샷건 스킬 필드를 덮어쓴다. 기존 표의 샷건 스킬 필드를 읽던 곳(가이드, 테스트)은 함께 고친다.
- **Rationale**: 사용자 선택. 리볼버·게틀링 스킬 값은 `gameTuning.ts`에 있는데 샷건만 `constants.ts`에 직접 적혀 있었다. 이번에 D03~D08로 값을 크게 바꾸고 봇 측정으로 여러 번 조정하므로 튜닝 위치를 한 파일로 모은다.

## D15. 낡은 문서 캡처는 구현 뒤 다시 찍어 교체한다
- **Chosen**: 마지막 Phase에 "문서 캡처 갱신" Task를 둔다. 기존 스크립트(`scripts/capture-all.mjs`, `capture-tutorial.mjs`, `capture-weapons-and-skills.mjs`)로 `docs/screens/`의 가이드(`screen-07*`, `screen-08*`, `screen-09*`)·로비(`screen-01*`)·튜토리얼 캡처를 새로 찍어 교체하고, README와 문서의 참조 경로를 확인한다.
- **Rationale**: 사용자 선택. 캡처가 이미 지금 화면과 다르고 이번 변경으로 더 어긋난다.

## D16. 스킬 폭발의 주인과 "박힌 채 죽는 경우"
- **Chosen**: 폭발 피해, 킬 점수, 콤보는 **스킬을 쓴 플레이어** 몫이다(`applySkillDamage`의 `ownerIndex`). 박힌 몬스터를 다른 플레이어가 평타로 죽이면 그 킬은 평타를 친 쪽 몫이다. 스킬을 쓴 플레이어가 이탈 중이어도 이미 박힌 폭발은 몬스터 상태라 그대로 진행되고 점수는 그 플레이어에게 기록한다. 박힌 몬스터가 폭발 전에 죽으면 **폭발 피해는 사라지고 폭발 연출(파편·소리)만 죽는 순간에 재생**한다.
- **Rationale**: 사용자 선택. 폭발 피해는 박힌 몬스터 자신에게만 주기로 했으므로(D02) 죽은 뒤에 줄 대상이 없다. 평타로 묶어 놓고 잡는 흐름이 자연스럽다.

## D17. 퍼짐 범위는 십자선 중심, 화면 거리 기준 (D05의 "1.5m" 수정)
- **Chosen**: 추가 명중 대상은 십자선에서 **화면상 일정 거리** 안의 몬스터다. 기존 판정(`findBestTarget`)이 십자선과 몬스터의 화면 거리(정규화 좌표 × 화면 비율)를 쓰므로 같은 방식이다. 출발값은 화면 높이의 약 15%이고, 연출 퍼짐 원(지금의 약 2배)과 같은 크기로 맞춰 "탄이 퍼진 곳에 있으면 맞는다"가 눈으로 일치하게 한다. 값은 `GAME_TUNING`에 두고 D08 측정 때 조정한다.
- **Rationale**: 사용자 선택. 판정이 미터가 아니라 화면 거리라서 월드 1.5m는 기존 방식과 맞지 않고 화면에서 붙어 보이는 먼 몬스터가 범위 밖이 된다.

## D18. 튜토리얼 3단계(스킬)를 무기 3종 라운드로 나눈다
- **Chosen**: 1·2단계(정밀 조준, 홀드 연사)는 샷건 그대로 두고, 3단계를 3라운드로 만든다. ① 샷건 → ② 리볼버 → ③ 게틀링 순서로 무기를 자동 교체하고(`weaponSystem` 교체 API), 라운드 시작마다 `refillSkillInstant()`로 스킬을 채운다. 표적은 정지한 몬스터 편대(5~6마리)를 재사용한다. 4단계(피버)는 샷건으로 돌아온다. 1·2단계 표적은 체력 1짜리를 한 발에 잡는 샷건 기준이라 무기별 전체 튜토리얼(무기 선택 방식)은 이번에 하지 않는다.
- **Rationale**: 사용자가 "튜토리얼이 무기별로 돼야 하지 않나"고 지적했다. 튜토리얼은 `startTutorialMode`가 샷건 Lv1로 고정해 리볼버 칼날·게틀링 거품 스킬은 한 번도 써 볼 수 없다. 무기별 전체 튜토리얼은 1·2단계 표적과 문구를 다시 짜야 해 범위가 커서 제외했다.

## D19. 튜토리얼 라운드의 진행 방식과 안내
- **Chosen**: 각 라운드에서 **단타는 횟수 제한 없이 자유롭게 쏴 보고, 스킬을 한 번 쓰면 통과**한다. 단, 샷건 라운드만 박힌 뒤 **폭발이 한 번 터진 후 약 0.5초 뒤**에 넘어간다(박혀서 터지는 것을 보여 주기 위해). `TutorialGuideOverlay`에 무기 이름, 한 줄 특징, 지금 할 일을 보여 준다(가이드 카드의 "한 줄 요약" D11과 같은 문장을 재사용). 폰 "휙" 스킬은 `TUTORIAL` 단계에서도 동작해야 한다(이미 튜토리얼 스킬 단계 D05로 처리됨, 확인만).
- **Rationale**: 사용자 지시("스킬 쓰면 통과, 단타는 스킬 쓸 때까지 쏴보게"). 횟수 조건을 두면 막히는 경우가 생긴다. 샷건 스킬은 박혔다 터지는 것이 핵심이라 폭발을 한 번 보여 준다.
- 문서·테스트: `docs/튜토리얼_훈련장_가이드.md`와 `tests/tutorial-and-guide.test.ts` 계열에서 3단계가 3라운드로 바뀐 구성, 라운드별 무기 교체, 스킬 통과 조건, 샷건 폭발 대기를 검증한다(자동 확정).

## D21. 가이드 이미지는 필요한 10장만 `public/guide/`로 복사한다 (계획 단계 추가 결정)

## D20. 측정 결과와 최종 값
- **Chosen**: 시작값을 그대로 유지한다(시작값 유지). 같은 세션(커밋 `f1c6a3e`, 80판, `minions-first`)에서 측정한 봇 클리어율은 **샷건 S 90% / 게틀링 G 56% / 리볼버 R 90%**이다. 합격선 G−3 ≤ S ≤ R+3(53 ≤ 90 ≤ 93)을 만족해 값 조정은 하지 않았다(조정 0회).
  - 최종 값: 추가 명중 마릿수 2/2/3/3, 비율 10/15/20/25%, 반경 0.30, 폭발 피해 0.7/0.8/0.9/1.0, 보스 피해 4/5/6/6, 샷건 피해 스케일 1.0.
- **Rationale**: D08의 규칙대로 기준선이 합격선 안에 들어와 조정이 필요 없었다. 샷건과 리볼버가 같은 90%라 샷건을 더 올리면 리볼버를 넘을 위험이 있고, 값을 바꾸지 않아 테스트·가이드 문서도 그대로 둔다. 측정 상세와 표는 [playtest-2026-11-09-shotgun-spread-and-plunger](../references/playtest-2026-11-09-shotgun-spread-and-plunger.md)에 있다.
- 주의: 2026-11-07 측정(샷건 63% / 게틀링 68% / 리볼버 70%)과 비교하면 게틀링은 내려가고 리볼버와 샷건은 올랐다. 서열 판단은 이번 세션 값으로만 했다.

## D23. 샷건 공격력 기준 정정: 클리어율이 아니라 공격력 (D07·D08 대체, 실행 중 정정)
- **정정 내용**: 사용자가 말한 "게틀링보다 강하고 리볼버보다 약해야 한다"는 **공격력** 얘기였다. 계획 단계에서 이를 봇 클리어율 목표(D08)로 잘못 바꿨고, P03 측정(샷건 90% / 리볼버 90% / 게틀링 56%)은 그 잘못된 목표에 대한 것이다. D08의 클리어율 서열 목표는 폐기하고, 측정 기록은 참고용으로만 남긴다.
- **Chosen**: 기준은 **탄창 대비 총 피해**(GREAT, 전탄 명중)로 하고, 리볼버는 관통을 포함한 최대치(15.4 / 16.5 / 27.7 / 43.5)를 그 무기의 공격력으로 본다. 샷건 단일 대상 값을 게틀링(11.3 / 16.8 / 24.0 / 37.5)과 리볼버(관통 포함) 사이로 맞춘다. 샷건 펠릿당 피해를 0.35/0.40/0.50/0.60에서 **0.34 / 0.33 / 0.33 / 0.41**로 낮춘다(한 발 1.05/1.60/2.50/3.60 → **1.02 / 1.32 / 1.65 / 2.46**, 탄창 대비 14.3 / 18.5 / 26.4 / 39.4). 샷건 스케일 1.0과 추가 명중 마릿수·비율(D05·D06)은 그대로다.
- **Lv1 원샷 규칙**: 사용자가 "Lv1 원샷도 안 지켜도 될 것 같다"고 했다. 다만 Lv1을 1.02로 두면 순서가 그대로 성립해서 이번에는 규칙을 깨지 않고 유지했다(규칙을 지킬 필요는 없어졌다).
- **알려진 한계**: Lv2는 게틀링(16.8)이 리볼버 관통 최대(16.5)보다 커서 순서가 원래 성립하지 않는다. 샷건을 게틀링 위(18.5)로 두었고 리볼버 관통 최대보다 약간 높다.
- **Rationale**: 샷건은 기존에도 단일 대상 기준 탄창 대비 피해가 가장 컸고(Lv4 57.6) 퍼짐까지 더해 더 강해졌다. 사용자의 의도는 샷건이 리볼버를 넘지 않는 것이다.
