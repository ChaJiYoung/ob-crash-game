# Decisions: 후반 속도, 보스 소환 개편, 똥 모양 포탄, 보스 처치 연출

- Date: 2026-11-05
- Status: Confirmed

수치 근거는 실제 엔진을 임시로 패치한 봇 시뮬레이션이다(무기·조건별 40~60판, 클리어율 오차 약 ±10%p). 사람 플레이 데이터가 아니며, 구현 뒤 속도 증가(D01)와 보스 개편(D03~D07)을 함께 적용한 합산 수치는 아직 재지 않았다. 임시 패치는 저장소에 넣지 않았다.

## D01. 후반 웨이브 속도: 증가율 8%, 오비 2.2, 병맥주 2.0
- **Chosen**: `GAME_TUNING.speedPerWave` 0.04 → 0.08(7웨이브 +48%), `TARGET_SPECS.obi.speedMps` 1.9 → 2.2, `bottle.speedMps` 1.5 → 2.0. 필굿 2.6, 카스 라이트 2.4, 한맥 2.0, 보스 0.85는 그대로. 분열한 작은 병의 속도(`monsters.bottle.childSpeedMps` 2.2)는 그대로 두며, 큰 병이 2.0이므로 역전은 생기지 않는다.
- **Rationale**: (사용자 선택: 후보 3안 중 A) 웨이브별 평균 기본 속도가 1웨이브 2.50, 5웨이브 2.09, 6·7웨이브 2.5 안팎으로 후반이 초반보다 느렸다. 5웨이브가 오비·한맥·병맥주(느린 종)뿐이기 때문이다. A안은 평균이 2.50 / 2.59 / 2.55 / 2.89 / 2.73 / 3.14 / 3.21로 5웨이브도 초반 이상이 된다. 사용자는 병맥주를 더 올리라고 했고, 후보 중 병맥주 2.0은 가장 낮은 값이다(2.3은 필굿에 가까워 개성이 사라짐). 봇 보통 기준 클리어율은 샷건 93%, 개틀링 97%(현재 100%).
- **영향**: 도감·가이드의 속도 문구(`GuideModal.tsx` 73·87행, `docs/몬스터_도감_설명서.md` 18·20행), `tests/shared-protocol.test.ts` 33행(병맥주 1.5), 기준 시간(`parTimeSec`)을 함께 바꾼다.

## D02. 보스 체력 상향
- **Chosen**: 보스 체력 3웨이브 냉각기 45 → 75, 5웨이브 냉각기 40×2 → 70×2, 7웨이브 냉각기 50×2 → 90×2, 대왕 120 → 200 (`GAME_TUNING.waves[i].boss.coolerHp`, `kingHp`).
- **Rationale**: (사용자 요청 "체력을 늘려", 수치는 후보 H3) 보스가 5~12초에 깨져서 소환을 거의 못 본다는 피드백. 개틀링은 3·5웨이브 보스가 5~6초에 끝난다. 개틀링 보스 피해 배율(2.2)은 소환이 체력 기준으로 바뀌므로 건드리지 않는다.

## D03. 대왕 방패 제거
- **Chosen**: 대왕의 방패를 없앤다. `boss.shieldHpThresholds`, `boss.shieldReleaseKills`, 엔진의 `updateKingShield`·`releaseKingShield`·`shieldKillCount`·`shieldThresholdIndex`, `isShielded`를 사용하는 보스 쪽 경로, 방패 구체 모델(`TargetModels3D.ts` shieldMesh)과 체력바 쪽 방패 표시, 가이드·문서의 방패 설명을 정리한다. 오비의 방패(`isGuarding`)는 다른 기능이므로 건드리지 않는다.
- **Rationale**: (사용자 선택 "방패를 없애자") 체력 구간에서만 소환하면 방패가 켜진 채 몬스터가 없어 7웨이브가 멈추는 경우가 있었다(방패는 몬스터 6마리 처치로 풀림). 모든 보스가 같은 규칙이 되어 단순해진다. 칼날·거품 코드의 `isShielded` 처리(P02/P03)는 보스 방패가 사라져도 무해하지만 죽은 분기가 되므로 함께 걷어낸다.

## D04. 보스 소환을 체력 구간 기준으로
- **Chosen**: 시간 간격 소환을 없애고, 각 보스(냉각기·대왕)가 자기 최대 체력 대비 99% / 66% / 33% 아래로 내려갈 때마다 4마리를 소환한다. 소환 횟수는 무기와 상관없이 보스당 3번(3웨이브 12마리, 5웨이브 24마리, 7웨이브 36마리). 필드 몬스터 수 상한(`summonMaxActive`)은 두지 않는다.
- **Rationale**: (사용자 선택: 체력 구간, 99·66·33, 4마리, 상한 없음) 시간 기준이라 빨리 깨면 소환을 못 봤다. 체력 기준이면 개틀링도 반드시 소환을 본다. 상한은 시뮬레이션에서 큰 차이가 없어(6마리 소환 기준 샷건 70%, 리볼버 93%, 개틀링 85%) 사용자 요청대로 뺀다.
- **경고(사용자도 확인함)**: 이 규모의 보통 봇 클리어율은 샷건 70%, 리볼버 93%, 개틀링 78%, 아주 부정확 봇은 샷건 5%, 리볼버 63%, 개틀링 30%로, 지금 보스전(100%)보다 훨씬 어렵다. 속도 증가(D01)와 겹치면 더 어렵다. 구현 뒤 합산 재측정을 하고, 직접 플레이 뒤 `GAME_TUNING.boss.summonCount`·구간 값으로 조정한다.

## D05. 낙하 위치는 지금 그대로
- **Chosen**: `boss.minionDrop`(6~14m, 좌우 ±0.55rad, 낙하 1.2초, 같은 소환끼리 최소 1.5m)은 바꾸지 않는다.
- **Rationale**: (사용자 선택) 9~16m로 멀리하면 4마리 소환의 샷건이 70% → 83%로 오르는 것을 확인했지만, 사용자는 지금 거리가 괜찮다고 했다. 낙하 몬스터는 방어선까지 약 3초(일반 웨이브 약 9초)라 같은 마릿수에서 더 위험한 점은 알려 두었다.

## D06. 소환 구현 규칙
- **Chosen**:
  - `spawnBossMinionWave(nowMs, count)`는 그대로 쓰고, 엔진의 `update`에서 보스별로 "지나간 구간 수"를 센다. 체력 비율 `hp / maxHp`가 구간 값 이하이면 한 번 소환하고 다음 구간으로 넘어간다. 한 프레임에 여러 구간을 건너뛰면 구간 수만큼 소환한다.
  - 기존 시간 소환 필드(`boss.firstSummonDelayMs`, `summonIntervalMs`, `summonAccel`, `summonMaxActive`, `summonRadiusM`, `lastBossSummonTimeMs`, `getBossSummonIntervalMs`, 엔진의 `lastBossSummonHpThreshold`)와 관련 테스트(`tests/boss-summon-acceleration.test.ts` 등)는 정리한다. `summonKinds`, `summonCount`(3 → 4), `summonDropChance`, 소환 연출 시간(1.8초, `isBossSummoning`)은 유지한다.
  - 소환 몬스터가 필드에 남은 채 보스가 죽으면 지금처럼 웨이브 종료를 막는다.
- **Rationale**: (코드 기반 확정) 칼날·거품의 구간 판정과 같은 "지난 구간" 방식이라 프레임이 길어도 놓치지 않는다. 보스 3웨이브 시작 직후 99% 구간은 첫 타격 직후에 나온다.

## D07. 보스 포탄은 시간 기준으로 유지
- **Chosen**: 보스의 포탄 발사(3500ms 간격, 필드 상한 `maxSimultaneous + 2`)는 바꾸지 않는다.
- **Rationale**: (코드 기반 확정, 요청 범위 밖) 사용자는 소환만 체력 기준으로 바꾸자고 했다.

## D08. 포탄을 똥 모양으로 바꾸고 발사 연출을 넣는다
- **Chosen**:
  - 모양: 갈색 소프트아이스 모양으로 3단을 쌓은 똥 모델. 빛(emissive)과 고리가 없고 뱅글뱅글 굴러온다. 아이템의 오라 고리·둥둥 뜨는 느낌과 겹치지 않게 한다. `createProjectileMesh3D`를 교체한다.
  - 발사 연출: 한맥·보스가 쏘는 순간 그 위치에서 갈색 덩어리가 뿜어져 나가고 짧은 연기(약 0.3초)가 난다. 엔진에 발사 사건(`ProjectileLaunchEvent`, 칼날 타격 사건과 같은 방식으로 `drain`)을 새로 만든다.
  - 요격: 맞혀서 터질 때 파편 색을 갈색으로(`resolveHitFxColor`의 `#f87171` 교체).
  - 날아오는 동안의 꼬리와 방어선 경고는 넣지 않는다.
- **Rationale**: (사용자 요청 "똥모양으로 발사하는 모양의 이펙트", 선택: 1번) 지금 포탄은 붉게 빛나는 구에 노란 고리라 아이템과 구분이 안 되어 맞히지 않아 체력을 잃은 경험이 있었다. 시야가 복잡해지지 않게 연출은 발사 순간과 요격 순간에 한정한다. 셰이더 예열 목록에 새 재질이 들어가야 한다(`createWarmupObjects`, `ShaderWarmup`).

## D09. 랭킹과 기준 시간
- **Chosen**: `RANKING_RULESET_VERSION`은 v4를 유지한다(직접 플레이 뒤 v5 여부를 정함, 이전 계획과 같은 방침). 웨이브 기준 시간 `parTimeSec`는 모든 변경이 들어간 뒤 `measure-wave-times.ts`로 다시 잰다.
- **Rationale**: (이전 결정 D10 이어받음) 속도와 보스 개편이 점수를 바꾸지만 직접 플레이 뒤 재조정될 수 있어 초기화를 두 번 하지 않으려는 방침이다. 버전을 올리면 되돌릴 수 없어 직전에 다시 확인한다.

## D10. 보스 처치 연출
- **Chosen**: 보스(마지막 한 마리)를 처치하면 다음 순서로 진행한다.
  1. 보스가 큰 폭발로 터진다(파편 대량, 폭발음). 엔진에 "보스 처치 사건"을 만들어 평타·칼날·거품·뚫어뻥으로 잡았을 때 같은 연출이 나오게 하나로 합친다.
  2. 필드에 남은 몬스터는 움직임을 멈추고(방어선을 넘지 않음, 체력 손실 없음) 0.1초 간격으로 연쇄로 터진다. 점수·아이템 드롭·분열·카드 킬 수에는 반영하지 않는다.
  3. 화면 중앙에 "BOSS DOWN!" 배너가 1.5초 뜬다.
  4. 연출이 끝나면 3·5웨이브는 보상 카드가 나온다. 7웨이브는 같은 연출 뒤 승리 결과 화면으로 넘어간다.
- **세부 기본값**: 연출 동안(1.5초) 게임 시계는 흐르지만 사격과 스킬 시전은 막고(탄약 소모 없음), 소환·포격·스폰도 멈춘다. 웨이브 클리어 시간 보너스는 보스를 처치한 시점에 정산한다(연출 시간은 포함하지 않는다). 일시 정지와 카드 선택의 시간 정지는 지금처럼 연출 타이머도 함께 멈춘다. 7웨이브의 정밀도 보너스는 연출이 끝나고 승리가 선언될 때 정산한다.
- **Rationale**: (사용자 요청, 선택: 1번) 지금은 보스가 터지면 필드의 몬스터가 폭발 없이 한꺼번에 사라지고(엔진이 목록을 비움) 곧바로 카드가 화면을 덮어서 "클리어했다"는 순간이 없었다. 연쇄 폭발과 배너로 그 순간을 만들고, 카드는 연출 뒤에 띄운다. 연출 중 입력을 막는 것은 카드 선택의 입력 잠금과 같은 취지의 기본값이며 인터뷰 중 이의가 없었다.
- **영향**: `handleMonsterKilled`의 보스 분기(`activeTargets = []`, 즉시 `declareVictory`/다음 프레임 카드), 카드 스폰 조건, `hudSnapshot`(배너 값), `PCGamePage`(배너), `GameCanvas3D`(폭발·연쇄), 사운드. 보스 방패(D03)가 사라지고 소환(D06)이 체력 기준이 되므로 같은 계획의 같은 Phase 근처에서 다룬다.

## 범위 밖 (이번 계획에 넣지 않음, 사용자에게 보고함)
- 보스 소환 몬스터가 방어선까지 약 3초라 일반 웨이브 몬스터보다 위험한 점(낙하 거리 조정으로 완화 가능, D05).
- 오비의 방패와 대왕 방패는 별개이며, 오비는 건드리지 않는다.
- 보스 포탄의 간격·상한은 시간 기준 그대로(D07).
- 색이 번쩍이는 타격 연출은 이전 결정대로 직접 플레이 뒤 검토.
